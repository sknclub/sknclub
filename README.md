# SKN CLUBS 2.0 — GitHub Pages + Supabase โดยตรง + GAS + Google Drive

**โรงเรียนสมุทรสาครบูรณะ | เอกสารติดตั้งและใช้งานฉบับภาษาไทย | 10 ตุลาคม 2569**

> ชุดนี้สร้างจาก `Code.gs` และ `Index.html` ต้นฉบับที่แนบมา แล้วใช้เว็บ Vue เดิมเป็นฐานในการคงหน้าตาและวิธีใช้งาน รายการแก้ไขสำคัญ: Supabase Direct Client, ระบบภาคเรียนแยกอิสระ, การคัดลอกข้อมูลแบบเลือกได้, GAS ใช้เฉพาะรูปภาพ/PDF/Email/JSON และลายเซ็นเป็นรูปภาพที่บันทึกลง Drive

## 1. แผนผังการทำงาน

```text
มือถือ / คอมพิวเตอร์
    |
    v
GitHub Pages ── Vue + Bootstrap ── web/index.html
    |
    +--- supabase-js (publishable key + Supabase Auth JWT)
    |       |
    |       +---- PostgreSQL Tables (อ่านแบบ RLS)
    |       +---- RPC / SQL Transaction (เขียนข้อมูลสำคัญพร้อมตรวจสิทธิ์)
    |       +---- Supabase Auth (บัญชีผู้ใช้)
    |
    +--- HTML form POST -> Apps Script Web App
            |
            +---- ตรวจ JWT/RPC สิทธิ์จาก Supabase
            +---- Google Drive: ภาพ, ลายเซ็น, PDF, JSON backup
            +---- MailApp: ส่งอีเมลรายงานพร้อม PDF
```

ไม่มี `Supabase Edge Function` หรือ API ตัวกลางเพื่อจัดการฐานข้อมูล ทุกการอ่าน/เขียนข้อมูลระบบทำจากหน้าเว็บด้วย `supabase-js` โดยตรงผ่าน Supabase Data API และ SQL RPC ที่มีการตรวจสิทธิ์จริงใน PostgreSQL (ไม่ใช่เพียงซ่อนปุ่มบนหน้าเว็บ) GAS **ไม่มีคำสั่ง CRUD ข้อมูลชุมนุม/นักเรียน/ครู** และไม่มี secret/service role key บนเว็บ

**ข้อเท็จจริงทางเทคนิค:** เบราว์เซอร์ไม่สามารถเปิด TCP connection ไป PostgreSQL ด้วย username/password DB อย่างปลอดภัย จึงต้องใช้ `supabase-js`/Supabase Data API ที่ใช้ publishable key + Auth JWT; นี่คือการให้หน้าเว็บคุยกับ Supabase โดยตรง *ไม่มี Edge Function เป็นตัวกลาง* ตามเป้าหมายของระบบ

## 3. ติดตั้ง Supabase — ทำตามลำดับ

### 3.1 สร้างโครงการ

1. เข้า [supabase.com](https://supabase.com/) และสร้าง Project ใหม่ เลือก Region ที่เหมาะสม เก็บรหัสผ่านฐานข้อมูลให้ปลอดภัย
2. เลือก **SQL Editor** → New query → คัดลอก **ทั้งหมด** จาก `supabase/migrations/202610100001_init.sql` → Run ให้สำเร็จ
3. เปิด SQL Editor ใหม่ → คัดลอก **ทั้งหมด** จาก `supabase/migrations/202610100002_browser_direct.sql` → Run ให้สำเร็จ
4. เข้า **Table Editor** ตรวจสอบว่าเห็น `periods`, `teachers`, `students`, `clubs`, `registrations`, `attendance`, `club_reports`, `period_config`, `period_teachers`, `student_accounts`, `backup_logs`
5. ตรวจสอบ `periods` มีแถวเริ่มต้น **1/2569** อยู่แล้ว หากโรงเรียนต้องการเทอมอื่น เริ่มสร้างหลังจากเข้าสู่ระบบ Admin

> ถ้าใช้ฐานข้อมูล Supabase รุ่นเดิมที่เคยติดตั้งชุดแรกไว้แล้ว ให้สำรองข้อมูล Supabase ของรุ่นนั้นก่อน แล้วรัน **เฉพาะ** ไฟล์ migration 002 หลังจากตรวจ schema ในรุ่นนั้นตรงกับไฟล์ 001 อย่าเพิ่งรันบนข้อมูลจริงโดยไม่ได้ทดสอบการย้ายเวอร์ชัน

### 3.2 ตั้ง Supabase Authentication

ใน Supabase Dashboard → Authentication:

- เปิดให้ลงทะเบียนบัญชี (Allow new users to sign up)
- เปิด Email provider
- **ปิด Confirm Email** สำหรับรูปแบบเข้าใช้ด้วยรหัสนักเรียน/รหัสครูของระบบนี้ (ผู้ใช้ไม่มีอีเมลจริงในระบบ Auth; ระบบใช้ที่อยู่อีเมลแบบสุ่มไม่สามารถคาดเดาได้)
- อย่าปิดการตรวจสอบสิทธิ์ JWT/RLS
- แนะนำให้ตั้ง CAPTCHA/การป้องกัน brute-force และใช้รหัสผ่านที่คาดเดายากสำหรับครูและผู้ดูแล

ระบบมีตารางบัญชีชื่อผู้ใช้/รหัสผ่านเดิม (bcrypt hash) และเมื่อเข้าสู่ระบบครั้งแรกจะสร้างบัญชี Supabase Auth ให้อัตโนมัติผ่านหน้าเว็บ ผู้ดูแลจึงนำเข้านักเรียนจำนวนมากทาง CSV ได้โดย **ไม่ต้องเรียก Signup ครั้งละนักเรียนทั้งโรงเรียน** และไม่ติด Signup rate limit ในขั้นตอนอัปโหลด CSV

รหัสผ่านที่สั้นตามระบบเก่าจะถูกตรวจด้วย bcrypt ก่อน จากนั้นส่งรหัสที่อนุพันธ์ด้วย SHA-256 ไปใช้กับ Supabase Auth เพื่อให้ผ่านกติกาความยาวรหัสผ่าน ผู้ใช้งานยังพิมพ์รหัสเดิมที่หน้า Login ได้

### 3.3 สร้าง Admin ครั้งแรก

เปิด SQL Editor **คัดลอกคำสั่งนี้แล้วเปลี่ยน `REPLACE_WITH_STRONG_PASSWORD` เป็นรหัสยาวอย่างน้อย 12–16 ตัว**

```sql
insert into public.teachers
 (id,name,username,password_hash,role,auth_email,auth_uid)
values
 ('T01','Admin ระบบ','admin',
  extensions.crypt('REPLACE_WITH_STRONG_PASSWORD',extensions.gen_salt('bf',10)),
  'admin','t-'||replace(gen_random_uuid()::text,'-','')||'@skn.example',null)
on conflict(id) do update set
  name=excluded.name,username=excluded.username,password_hash=excluded.password_hash,
  role='admin',auth_email=excluded.auth_email,auth_uid=null;

insert into public.period_teachers(period_id,teacher_id,display_name)
select id,'T01','Admin ระบบ' from public.periods where is_current
on conflict(period_id,teacher_id) do nothing;
```

**ห้ามนำรหัสผ่านจริงไปใส่ README, GitHub หรือภาพหน้าจอ** ให้เปลี่ยนใน SQL Editor อย่างเดียว และหลังติดตั้งเสร็จควรบังคับให้ผู้ใช้ครูเปลี่ยนรหัสเริ่มต้นที่คาดเดาง่าย

### 3.4 นำ URL และ Publishable Key ไปใส่เว็บ

ใน Supabase → Project Settings → API Keys/Connect:

- Project URL เช่น `https://abcxyz.supabase.co`
- Publishable key เช่น `sb_publishable_...` (หรือ legacy `anon` key ที่โครงการรองรับ)

แก้ไฟล์ `web/config.js`:

```js
window.SKN_CONFIG = {
  supabaseUrl: 'https://abcxyz.supabase.co',
  publishableKey: 'sb_publishable_xxxxxxxxxxx',
  gasWebAppUrl: 'https://script.google.com/macros/s/AKfycbxxxxxxxxx/exec'
};
```

Publishable key ใส่ GitHub Pages ได้เมื่อเปิด RLS ถูกต้อง **อย่าใส่ `service_role`, secret key, JWT signing secret หรือรหัสผ่านฐานข้อมูลลงในไฟล์เว็บ**

## 4. ตั้ง Google Drive + Google Apps Script

### 4.1 Drive

1. เปิด Drive บัญชีโรงเรียน/บัญชีผู้ดูแลที่มีสิทธิ์ถาวร
2. สร้างโฟลเดอร์ เช่น `SKN_Club_Storage` และให้สิทธิ์เฉพาะผู้ดูแล (ห้าม Anyone with link)
3. เปิดโฟลเดอร์ URL `https://drive.google.com/drive/folders/FOLDER_ID` แล้วคัดลอก `FOLDER_ID`
4. ระบบจะสร้างโฟลเดอร์ย่อยเอง เช่น `SKN_Club_Media`, `SKN_PDF_Reports`, `SKN_Club_Backups`

### 4.2 GAS

1. เข้า [script.google.com](https://script.google.com/) → New project → เปลี่ยนชื่อ `SKN-FILE-SERVICE-V2`
2. ลบโค้ดเริ่มต้นใน `Code.gs` แล้ววางไฟล์ `gas/Code.gs` ทั้งหมด
3. Project Settings → **Script Properties** → Add properties ดังนี้:

| Property | ค่า |
| --- | --- |
| `SUPABASE_URL` | `https://abcxyz.supabase.co` |
| `SUPABASE_PUBLISHABLE_KEY` | publishable/anon key เดียวกับเว็บ |
| `SKN_DRIVE_FOLDER_ID` | Folder ID จากข้อ 4.1 |
| `SKN_ALLOWED_ORIGINS` | `https://YOUR_GITHUB_USERNAME.github.io` (ไม่ต้องลง path) |

กรณีทดสอบจากเครื่องเดียวกันด้วย Python web server ให้เพิ่ม `http://localhost:8000` โดยคั่นด้วย comma ส่วน GitHub Pages URL `https://username.github.io/repository/` มี **Origin** เป็นแค่ `https://username.github.io` เท่านั้น

4. Run ฟังก์ชัน `authorizeServices` จาก Apps Script Editor เพื่ออนุญาต DriveApp, MailApp และ UrlFetchApp (ถ้าระบบขอสิทธิ์)
5. Deploy → New Deployment → **Web app** → Execute as **Me** → Who has access **Anyone** → Deploy
6. คัดลอก URL ที่ลงท้าย `/exec` ไปใส่ `gasWebAppUrl` ของ `web/config.js`

> แม้ GAS Web App อนุญาต Anyone ให้เข้าถึง endpoint แต่คำสั่งบันทึก/อ่านไฟล์ **ทุกคำสั่ง** จะตรวจสิทธิ์ JWT กับ Supabase (`skn_file_permission` และ `skn_file_reference`) ก่อนทำงาน ผู้ที่ไม่มีบัญชี/สิทธิ์ของปี/ชุมนุมนั้นจึงไม่ควรอ่านไฟล์ได้ ทั้งนี้อย่าเผยแพร่ URL พร้อม access token ในแชทสาธารณะ

### 4.3 การส่งไฟล์ระหว่าง GitHub กับ GAS

ระบบใช้ **POST จาก `<form>` ไปยัง iframe ที่ซ่อนอยู่** และรับผลกลับด้วย `postMessage` + nonce ไม่ใช้ CORS `fetch` ตรงไป GAS ซึ่งมักถูกเบราว์เซอร์บล็อกเมื่อรัน GitHub Pages ข้ามโดเมน สามารถเปิดดู Network ใน DevTools เพื่อตรวจว่ามี `POST /exec` และผลยืนยันกลับมา

## 5. เผยแพร่หน้าเว็บด้วย GitHub

1. สร้าง GitHub Repository ใหม่ เช่น `skn-clubs` (แนะนำ private ระหว่างกำลังทดสอบ)
2. Upload ทุกไฟล์/โฟลเดอร์ในชุด ZIP โดยคงโครงสร้างเดิม รวม `web/`, `gas/`, `supabase/`, `tests/`, `.github/`
3. ตั้งค่าไฟล์ `web/config.js` ที่ได้จากขั้นตอน 3–4
4. ไปที่ GitHub → Settings → Pages → Source: **GitHub Actions**
5. Workflow `.github/workflows/pages.yml` จะส่งขึ้น Pages จากโฟลเดอร์ `web/` เมื่อ push ไป branch `main`
6. เปิด URL `https://USERNAME.github.io/skn-clubs/` → ล็อกอิน Admin จากข้อ 3.3
7. หากใช้ Repo private ต้องตรวจสิทธิ์ GitHub Pages ของแผนบัญชีจริง (การที่ Repo private ไม่ได้หมายความว่า Pages เป็น private)

**ไม่มีขั้นตอน deploy Edge Function** และไม่ต้องตั้งค่า `SUPABASE_SERVICE_ROLE_KEY` ในเว็บหรือ GAS

## 6. การใช้งาน CSV จากหน้าเว็บเดิม

เข้าสู่ระบบ Admin → **จัดการผู้ใช้** → เลือกแท็บ **นักเรียน** หรือ **คุณครู** → **นำเข้า/อัปเดตรายชื่อ CSV**

### นักเรียน (`examples/students.csv`)

```csv
id,name,level,room,no,password
69001,"เด็กชายสมชาย ใจดี",ม.1,1/1,1,01/01/2555
69002,"เด็กหญิงสมใจ ใจดี",ม.1,1/1,2,02/02/2555
```

### ครู (`examples/teachers.csv`)

```csv
id,name,username,password,role
T02,"ครูตัวอย่าง",teacher02,CHANGE_ME_STRONG_PASSWORD,teacher
```

- ต้องเป็นไฟล์ **UTF-8 CSV**, รองรับ BOM, คั่น comma หรือ semicolon, รองรับข้อความที่มี `,` ในชื่อโดยใส่เครื่องหมายคำพูดครอบ
- นักเรียนควรเก็บรหัส ID เป็นข้อความเพื่อไม่ให้เลข 0 นำหน้าหาย; รหัสวันเกิดเก็บเป็นสตริง เช่น `01/01/2555`
- ระบบ **เพิ่มใหม่/อัปเดต** จาก ID และกัน ID ซ้ำในไฟล์, ส่งข้อมูลครั้งละ 150 รายการด้วย `skn_upsert_users()` SQL RPC ซึ่งทำงานเป็นชุด transaction ต่อ batch
- หากช่อง Password ในไฟล์ของแถวเดิมว่าง จะคงรหัสเดิม; หากเปลี่ยน Password จะสร้างบัญชี Auth ที่อยู่ภายในใหม่เมื่อเจ้าของล็อกอินครั้งต่อไป และบัญชีเก่าจะหมดสิทธิ์อ่านข้อมูล
- Password ของแถวใหม่ที่ว่างจะใช้ ID เป็นค่าเริ่มต้นเพื่อความเข้ากันได้กับระบบเดิม **แต่ไม่ปลอดภัย** จึงควรกรอก Password ทุกครั้ง
- การดาวน์โหลด CSV รายชื่อกลับจากระบบ **ไม่มีรหัสผ่านจริง** เพราะไม่มีการเปิดเผย hash หรือรหัสผ่านย้อนหลัง และช่อง password ถูกปล่อยว่างแทน
- หลังการนำเข้า ตรวจจำนวนคนด้วยหน้าสรุปและทดสอบบัญชีนักเรียนตัวอย่าง 2–3 ราย ก่อนเปิดใช้งานจริง

**สถานะทดสอบ CSV:** ตัวอ่าน CSV/จำนวน/เครื่องหมายคำพูดผ่านชุดทดสอบ `npm test` แต่การอัปโหลดกับโปรเจ็กต์ Supabase จริงต้องทดสอบหลังตั้งค่า ไม่อ้างว่าทดสอบบนฐานข้อมูลของโรงเรียนแล้ว

## 7. การเริ่มเทอม/ปีการศึกษาใหม่ (สำคัญ)

Admin → **ตั้งค่าระบบขั้นสูง** → หัวข้อ **5. เริ่มภาคเรียนใหม่** → เลือกข้อมูล → ระบุเทอม/ปี → ยืนยัน

ระบบ *สร้างแถว `periods` ใหม่* และคัดลอกข้อมูลไปปีใหม่ใน transaction เดียว ไม่ลบแถวปีเก่าทิ้ง ก่อนสร้างเทอมจะส่งไฟล์ JSON snapshot ของภาคเรียนต้นทางไป Google Drive; หากสำรองไม่สำเร็จจะ **ไม่เริ่มสร้างเทอม**

เลือก **คัดลอก/ไม่คัดลอก** อย่างอิสระตามกลุ่มข้อมูล 6 ประเภท:

| กลุ่มข้อมูล | เลือก = คัดลอก | ไม่เลือก = เปิดเทอมใหม่โดยไม่คัดลอก |
| --- | --- | --- |
| ครู | ครูประจำเทอมเดิม (Admin ยังคงอยู่เสมอ) | ครูอื่นต้องเข้าร่วมเทอม/นำเข้าใหม่ |
| นักเรียน | รายชื่อนักเรียน/ห้อง/เลขที่ | นักเรียนเทอมใหม่ว่าง รอนำเข้า CSV |
| ชุมนุม | ชื่อชุมนุม ระดับ จำนวนรับ ผู้ดูแล และสถานที่ | ชุมนุมว่าง ให้สร้างใหม่ |
| การลงทะเบียน | นักเรียนสังกัดชุมนุมเดิม | ไม่คัดลอกการสมัคร ยอดเริ่มที่ 0 |
| การเช็กชื่อ | ตารางวันที่/สถานะเดิม 20 ครั้ง | เริ่มเช็กชื่อใหม่ 20 ครั้งโดยไม่มีประวัติ |
| รายงาน | ข้อความ/อ้างอิงภาพลายเซ็นและรูปภาพเดิม | รายงานใหม่ว่าง |

**ความสัมพันธ์ที่ระบบตรวจอัตโนมัติ:**

- จะคัดลอก **การสมัคร** ต้องคัดลอกทั้ง **นักเรียน** และ **ชุมนุม**
- จะคัดลอก **การเช็กชื่อ** ต้องคัดลอก **การสมัคร** ด้วย
- จะคัดลอก **รายงาน** ต้องคัดลอก **ชุมนุม** ด้วย
- หากคัดลอก **ชุมนุม** โดยไม่คัดลอก **ครู** จะสร้างชุมนุมไว้โดยไม่มีที่ปรึกษา ต้องให้ Admin กำหนดครูใหม่ก่อนครูจะใช้งานได้
- เทอมใหม่ล้างค่า **วันที่กิจกรรมส่วนกลาง/วันหยุดส่วนกลาง** เพื่อให้ตั้งใหม่ ไม่กระทบตารางเช็กชื่อที่เลือกคัดลอก; เมื่อต้องการคัดลอกเช็กชื่อเดิม ให้ตรวจวันที่บนหน้าตารางให้เหมาะกับเทอมใหม่

## 8. ภาพ ลายเซ็น PDF และรายงาน

- ภาพโลโก้กิจกรรมและภาพการดำเนินงาน 4 ช่องถูกบีบอัดบนหน้าเว็บ แล้วส่งผ่าน GAS ไป Drive; ใน Supabase เก็บ **เฉพาะ ID/Hash/MIME**
- ช่องลายเซ็นในหน้า **รายงานชุมนุม** (ครูที่ปรึกษา หัวหน้าชุมนุม หัวหน้ากิจกรรม รองผู้อำนวยการ ผู้อำนวยการ): บริเวณว่างไม่มีเส้นประและไม่แสดงคำว่าคลิก → คลิกพื้นที่ว่าง → เลือกภาพ PNG/JPG/WebP → บันทึกอัตโนมัติไป Drive พร้อมรายงาน
- หน้า **Admin Report** ใช้พื้นที่ว่างแนบลายเซ็น 3 จุดและบันทึกอ้างอิงรูปลง `period_config.adminSettings.signatureFiles`
- แนะนำภาพ **PNG พื้นหลังโปร่งใส** เพื่อได้ลายเซ็นเหมือนเซ็นบนเอกสาร; รูปจะถูกรักษาความโปร่งใสด้วย Canvas PNG
- PDF: ดาวน์โหลด/พิมพ์ด้วยกลไกเดิม และมีปุ่มส่ง PDF ที่เลือกเก็บลง Drive ผ่าน GAS; Email แนบ PDF ผ่าน MailApp
- หากคัดลอกรายงานข้ามเทอม รหัสภาพจะอ้างถึงไฟล์ Drive ของเทอมต้นทาง ระบบตรวจสิทธิ์ผ่านรหัสอ้างอิงฐานข้อมูลเพื่อเปิดดูภาพได้ **ห้ามลบโฟลเดอร์เทอมเก่าที่มีภาพที่ถูกคัดลอกอ้างถึง**

## 9. หน้าตา/การคำนวณที่ยึดของเดิม

- UI `Index.html` Vue+Bootstrap เดิม, Dashboard, ตารางชุมนุมและสมัคร/ย้าย, หน้าครู/Admin, ค้นหารายห้อง, สรุปข้อมูล, ตารางเช็กชื่อ 20 สัปดาห์, รายงาน Word/พิมพ์/PDF/Email
- ครู **20 คนต่อที่ปรึกษา 1 คน** (ตามโค้ดเดิม), Admin ระบุความจุเอง
- สมาชิกชุมนุมได้จากจำนวนรายการลงทะเบียนจริง (ไม่เก็บตัวนับแยกที่อาจคลาดเคลื่อน)
- เช็กชื่อ: `0=ยังไม่บันทึก, 1=มา, 2=ลา, 3=ขาด`; ผลเดิม **ไม่ผ่าน** เมื่อไม่มี 'มา' เลย หรือ 'ขาด' > 3 ครั้ง; ไม่เปลี่ยนสูตร/การนับเดิม
- หัวข้อ **3** ในหน้าตั้งค่าขั้นสูงเป็น **กำหนดวันที่จัดกิจกรรมชุมนุม (20 สัปดาห์)** อยู่ซ้าย; หัวข้อ **4** เป็น **กำหนดวันหยุด** อยู่ขวา
- `startNewSemester` เป็นการสร้างเทอมใหม่ด้วยตัวเลือกแทนการล้างข้อมูลจากตารางเดิม

## 10. ย้ายข้อมูลจากชีต Google เดิม

**ทำในฐานทดสอบก่อนทุกครั้ง:**

1. สำรอง Google Sheets และ Apps Script เดิมเก็บไว้ใน Drive โดยไม่ทับไฟล์เดิม
2. เปิด Apps Script ผูกกับชีตเดิม แล้ววาง `tools/ExportLegacy.gs` และ Run `exportLegacySKN()` → ระบบสร้างไฟล์ `skn-legacy.json` ใน Google Drive
3. ดาวน์โหลด JSON ลงเครื่อง (ไฟล์มีรหัสผ่านเดิมเป็น plain text; ระวังเป็นพิเศษ)
4. เปิดหน้าเว็บ `https://YOUR_USER.github.io/REPO/import-legacy.html` และเข้าสู่ระบบ Admin
5. เลือก JSON แล้วนำเข้าตามลำดับระบบ: Teachers → Students → Clubs → Registration → Attendance_Data → Club_Reports → Config
6. ตรวจเทียบสถิติเดิมกับใหม่ รวมยอดสมาชิก/สถานะเช็กชื่อ/รายงาน และทดสอบการคลิกเปิดรูป Drive
7. เมื่อย้ายสำเร็จ ลบไฟล์ส่งออกที่ไม่จำเป็นออกจากคอมพิวเตอร์และจัดเก็บไฟล์สำรองไว้ในโฟลเดอร์ส่วนตัวที่ปลอดภัย

ไฟล์นี้ใช้สำหรับย้ายข้อมูลครั้งแรก **ไม่ใช่ปุ่ม Import CSV ปกติ**; CSV ปกติใช้เมนูจัดการผู้ใช้บนหน้าเว็บหลัก

## 11. ตรวจรับระบบ 16 กรณีก่อนเปิดใช้จริง

1. Admin Login/Logout สำเร็จ, นักเรียน Login ด้วย ID และวันเกิดที่จัดไว้
2. ครู Login และเห็นเฉพาะชุมนุมที่ตนเป็นเจ้าของในเทอมปัจจุบัน
3. Admin สร้าง/แก้ไข/ลบชุมนุม, ครูสร้างชุมนุมโดยโควตา 20 คนต่อครู
4. นักเรียนสมัครชุมนุมขณะเปิดรับ → ยอดเพิ่ม 1; เมื่อเต็มปุ่มแจ้งเต็ม
5. นักเรียนย้ายชุมนุมขณะเปิดให้ย้าย → คืนที่ว่างเดิมและเพิ่มใหม่ได้ถูกต้อง
6. ล็อกปิดสมัครแล้ว นักเรียนสมัครใหม่ไม่ได้แม้เรียก Supabase RPC ตรง
7. ตารางเช็กชื่อ 20 ครั้งบันทึก/โหลดกลับมาได้ครบ 0–3
8. ตรวจผล 'ไม่ผ่าน' เมื่อมา 0 ครั้ง หรือขาด 4 ครั้ง; มา 1 ครั้ง ขาด 3 ครั้ง ยังผ่าน
9. CSV UTF-8 ที่มีชื่อไทยและเครื่องหมาย comma สามารถเพิ่ม/อัปเดตผ่านหน้าเว็บได้
10. CSV มีข้อมูลซ้ำ ID รายงานจำนวนที่ข้าม/เพิ่ม/แก้ไขถูกต้อง
11. รายงานบันทึกข้อความ โลโก้ ภาพ 1–4 ลง Drive แล้วโหลดกลับได้
12. คลิกบริเวณลายเซ็นว่างในรายงาน → เลือกรูป PNG → บันทึกและพิมพ์ได้โดยไม่มีเส้นประ
13. แนบ PDF และส่ง Email ได้ (ตรวจโควตาส่งเมลของบัญชี Google)
14. เทอม 2 แบบคัดลอกครู/ชุมนุม/นักเรียน/ลงทะเบียน แต่ไม่คัดลอกเช็กชื่อและรายงาน คงยอดคนเดิม
15. ลองอีกชุดโดยไม่คัดลอกชุมนุมและนักเรียน → ข้อมูลปีใหม่ว่างและรองรับ CSV ใหม่ (ทดสอบบนฐานจำลอง)
16. ครูและนักเรียนเปลี่ยนไปปีเก่าแล้วแก้ไข/ส่ง RPC เขียนข้อมูลไม่ได้; Admin แก้ไขย้อนหลังได้

ทดสอบพื้นฐานใน ZIP ด้วย `npm test` (ต้องมี Node.js) และ `npm run check:web`; หากแก้ `web/backend.ts` ให้รัน `npm install` แล้ว `npm run build` เพื่อสร้าง `web/backend.js` ใหม่

## 12. การสำรอง/กู้คืน และข้อจำกัดที่ต้องทราบ

การขึ้นเทอมใหม่สำรองไฟล์ JSON `SKN_Backup_Term...json` ลง Drive ครอบคลุมข้อมูลภาคเรียน: ครูที่อยู่ในเทอม รายชื่อนักเรียน ชุมนุม การสมัคร เช็กชื่อ รายงาน ID ภาพ และ Config ประจำเทอม; และบันทึก ID ไฟล์ใน Supabase `backup_logs`

**สิ่งที่ snapshot เทอมไม่ได้สำรองทั้งหมด:** ตัวไฟล์ภาพ/PDF/ลายเซ็นจริงเก็บแยกใน Drive; บัญชี Supabase Auth และรหัสผ่าน hash ที่ถูกปิดการอ่านจากหน้าเว็บไม่ได้รวมใน JSON snapshot; ประวัติภาคเรียนอื่นไม่ได้ถูกสำรองพร้อมกัน ดังนั้นเพื่อการกู้คืนภัยพิบัติจริงต้องใช้ **Supabase database backup** และสำรองโฟลเดอร์ Drive แยกตามนโยบายโรงเรียน รวมถึงสำรอง GitHub Repo

**ยังไม่มีการทดสอบ end-to-end กับ Supabase/Google Drive ของโรงเรียน** เพราะไม่มี Project URL, key, Deploy GAS และบัญชีทดสอบจริงจากโรงเรียน จึงไม่สามารถรับรอง "เหมือนเดิม 100%" ในการใช้งานจริงก่อนทำข้อ 11 แต่ชุดนี้รักษาโครงสร้าง UI, ชื่อฟังก์ชันเดิม และเกณฑ์คำนวณที่ตรวจจากต้นฉบับไว้

### ข้อควรระวังด้านข้อมูลส่วนบุคคล

ระบบมีชื่อ ห้อง เลขประจำตัว วันเกิด/รหัสเข้าใช้เด็ก และรายงานกิจกรรม: ให้ใช้บัญชีโรงเรียน, ตั้ง RLS, ไม่แชร์ Drive เป็น Anyone with link, ไม่โพสต์ข้อมูล CSV/JSON ลง GitHub, ไม่ส่งรหัสผ่านผ่านอีเมลที่ไม่ปลอดภัย และควรใช้รหัสผ่านสุ่มแทนวันเกิดเมื่อมีโอกาส
